# 扩展 TUI 规范

本规范适用于仓库内各扩展的终端界面：以 Pi 原生 UI 和组件为实现基线，统一操作习惯、视觉语义和验收要求，不要求不同场景使用同一种界面。

“必须”是新增或实质修改相关界面时的验收要求；“推荐”允许在原生 API 或既有业务约束不适配时采用有测试支撑的替代方案。本文规定目标行为，不代表存量界面已经全部符合。

## 1. 边界与组件选型

界面调整必须保留命令、工具、配置、记录协议和公开入口的兼容性。不得借统一界面改变业务规则、增加模型调用、刷新外部目录或自动保存配置。各包继续独立安装和发布，不跨包引用未发布的源码，不新增第二套终端渲染器。

按“Pi 对话框 → 原生组件组合 → 必要的自定义组件”的顺序选择。已有能力能满足需求时，不重写对应基础控件。

| 场景 | 选型 |
|---|---|
| 简单选择、确认、单行输入 | `ctx.ui.select()`、`confirm()`、`input()` |
| 多项设置 | 推荐 `SettingsList`；复杂值由子界面编辑 |
| 可搜索列表 | 原生 `Input` 配合 `SelectList` 或必要的列表适配层；搜索规则保留在业务层 |
| 文本和 Markdown | `Text`、`TruncatedText`、`Markdown`，配合 Pi 的主题辅助函数 |
| 子代理会话 | 保留 Pi 原生消息、工具执行和摘要组件 |
| 长内容滚动 | 优先接入 `ScrollView`；不适配时使用职责单一、经过边界测试的视口适配层 |
| 常驻摘要和非阻塞反馈 | `setWidget()`、`setStatus()`、`notify()` |

不得自行实现字符级输入、输入光标、Markdown 解析和 ANSI 列宽计算。`ScrollView` 依赖布局系统，不能只调用其 `render()` 就假定已完成裁剪；改造时必须核对真实布局行为。原生完整业务组件也不等于无副作用的基础控件，使用前必须核对其加载、刷新、持久化和销毁行为。

## 2. 布局与视觉

### 原生界面与自定义面板

原生对话框保持 Pi 自带外观，不额外套壳。自定义面板采用以下信息顺序，按需省略搜索区和反馈行：

```text
标题                              数量 / 状态
──────────────────────────────────────────
搜索或筛选区
主体列表 / 详情
──────────────────────────────────────────
操作反馈
快捷键提示
```

必须区分标题、主体、反馈和操作提示。推荐横向分隔线，不再为相同用途分别维护直角、圆角等多套封闭外框。内容留白遵循 Pi 的 `outputPad` 设置，避免内外重复填充。

标题和底部操作区必须在可交互尺寸内可见，主体负责滚动。不得依赖弹窗的高度裁剪隐藏多余内容，导致操作区被裁掉。

### 主题语义

| 内容 | 主题语义 |
|---|---|
| 标题、主要强调 | `accent` |
| 正文 | `text` |
| 次要信息 | `muted` |
| 辅助提示 | `dim` |
| 分隔线 | `borderMuted` |
| 成功、警告、错误 | `success`、`warning`、`error` |
| 自绘列表选中背景 | `selectedBg` |

必须使用 Pi 当前主题，不硬编码 RGB 或 ANSI 颜色。原生控件保留自身主题适配；自绘选中项必须同时具有位置标记和高亮，不能只靠颜色区分。普通面板背景推荐使用与 Pi 一致的语义背景色，不把静态面板误标为成功或失败。

### 尺寸与窄屏

自定义覆盖层采用两档推荐默认值，均受实际终端宽高和外边距约束：

| 类型 | 用途 | 推荐默认值 |
|---|---|---|
| 标准面板 | 设置、搜索选择、监听列表 | 宽度 80%，最小宽度目标 30 列，最大高度 80%，外边距 1 |
| 阅读面板 | 子代理会话、长详情 | 宽度 90%，最大高度 85%，外边距 1 |

内嵌原生选择器不必改为覆盖层。最小宽度是目标，不得为了满足它而溢出实际终端。

必须以 compositor 传入的宽度布局，并按实际可用高度计算主体行数，固定页长只能作为上限。窄屏先隐藏时间、ID 等次要字段，保留名称、状态和关键操作。尺寸不足以容纳主体时，显示可见的缩放提示并保留退出能力。

每行可见宽度不得超过传入宽度。使用 `visibleWidth()`、`truncateToWidth()`、`sliceByColumn()`、`wrapTextWithAnsi()` 等内置工具，不用字符串长度替代终端列宽。

## 3. 键盘、搜索与焦点

原生组件自行处理已有按键；自定义组件的导航、翻页、确认和取消必须接入 Pi 注入的 `keybindings`。底部提示必须反映实际绑定，不把固定的方向键、Enter、Esc 提示当作唯一可配置按键。

业务快捷键只在对应页面生效，不能抢占搜索输入。额外的 `j/k` 等别名属于可选能力，不得妨碍输入或取代原生绑定。

所有文字编辑必须交给原生 `Input` 或 `Editor`。包含它们的包装组件必须实现 `Focusable`，并将 `focused` 传播给当前输入组件，以正确定位输入法候选窗口。输入应支持中文、emoji、多字符粘贴、退格和编辑快捷键；不得以 `data.length === 1` 限制输入。

取消逐层返回或关闭，不隐式保存或触发业务操作。子界面结束后，父界面必须恢复合理的焦点和选择状态。优先使用受控页面切换，避免为简单编辑堆叠多层覆盖层。

## 4. 列表与滚动

列表必须满足以下不变量：

1. 当前选中项始终可见；超过一屏后，窗口随选中项移动。
2. 对动态列表，操作对象以稳定 ID 确定，而不是刷新后可能变化的数组位置。
3. 筛选、数据更新和缩放后，选中项与滚动位置仍合法；被选对象消失时采用明确且可见的回退。

可以限制一页最多渲染多少项，但不能只绘制前 N 项、仍让选中索引继续下移。翻页和首尾边界必须与真实可见行数一致。不得让隐藏的选中项继续接受停止、恢复等业务操作。

阅读视图必须限制滚动范围。实时内容仅在用户位于底部时跟随；用户上翻后暂停跟随，回到底部后恢复。保留既有增量渲染和缓存，不为统一外框重复渲染整份会话。

## 5. 保存、反馈与确认

设置界面必须明确选择一种保存模式，不能混用：

| 模式 | 行为 |
|---|---|
| 单项即时修改 | 明示“修改立即生效”，保存成功后反馈；取消只返回，不承诺撤销 |
| 多项草稿编辑 | 明示“未保存”，提供独立保存动作；取消不落盘，必要时提示放弃修改 |

通知设置保留草稿保存语义。采用 `SettingsList` 时，Enter 用于激活当前设置项，不得同时被整页保存截获；整页保存通过明确的保存项或操作完成。子界面的模型选择在草稿流程中只更新草稿，独立模型选择命令则在确认后持久化。

成功操作必须有简短反馈；错误说明失败对象、原因和可采取的下一步，不覆盖用户输入。异步操作执行中必须防止重复触发和关闭后的迟到更新。

不可恢复或批量危险操作必须显式确认，并标明目标和后果。实时列表中的确认必须绑定稳定 ID；切换目标或返回时取消旧确认。

扩展自有界面默认使用中文，命令、模型名、路径和用户内容保持原样；不为统一文案重写 Pi 原生组件的内部文本。

## 6. 模式与生命周期

- 只有 `ctx.mode === "tui"` 才创建自定义终端组件；`hasUI` 不代表支持 custom TUI。
- RPC 支持的交互使用原生对话框或文本反馈；非交互模式不挂载终端组件，业务执行与渲染解耦。
- 每次交互创建独立组件，用工厂提供的 `done()` 结束，关闭逻辑必须幂等。不手动隐藏由 `ctx.ui.custom()` 管理的覆盖层。
- 状态变化后，清理受影响缓存并调用注入的 `tui.requestRender()`。
- `invalidate()` 必须清理缓存或重建已着色内容；主题变化后不得残留旧 ANSI 颜色。
- `dispose()` 必须清理定时器和订阅，并阻止迟到的异步结果更新已关闭页面。
- `render()` 只读展示状态，不写配置、不发请求、不触发业务操作。布局缓存可更新，但不得在绘制时改变业务选择或操作对象。

## 7. 验收

新增或实质修改自定义交互组件时，按实际风险提供自动化验证：

| 维度 | 必验内容 |
|---|---|
| 数据 | 空列表、单项、超过一屏；选择项消失或列表重排 |
| 导航 | 上下、翻页、首尾边界、筛选后选择；选中项始终可见 |
| 尺寸 | 窄屏、常规宽度、短终端、打开期间 resize；操作区可见 |
| 输入 | 中文、emoji、多字符粘贴、退格、焦点传播 |
| 主题 | 明暗切换和 `invalidate()` 后没有旧颜色残留 |
| 生命周期 | 关闭后无定时器或订阅残留；异步结果不更新已关闭页面 |
| 模式 | TUI 正常；RPC 不创建 custom TUI；非交互业务不受影响 |
| 行为 | 取消不误保存；打开面板不新增业务副作用；错误保留草稿 |

组件测试必须断言实际对象、可见范围、行宽、焦点和资源清理，不能只依赖字符串快照。使用原生组件不等于豁免包装层的焦点、布局和按键路由验证。

涉及交互和布局的改造，另做无模型调用、无真实业务操作的隔离 TUI smoke，覆盖普通模式与 fullscreen 下的关键流程、缩放和退出。真实输入法候选窗口或终端主题行为无法自动验证时，必须说明未覆盖范围，不能把 `CURSOR_MARKER` 的组件测试等同于真实输入法验收。

命令、验证范围与交付要求见仓库 [协作规范](../../AGENTS.md)。只有相关验证通过，或已明确报告环境阻塞与替代证据，才交付该界面的改造。
