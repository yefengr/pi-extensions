# 子代理扩展上游改进同步方案

状态：方案草案，**尚未实施，也未获实施批准**。本文记录拟采纳的范围、行为边界、兼容约束和验收要求；不表示上述能力已经可用。文中标注“待验证”的风险来自源码核对或上游变更记录，尚未在真实任务中复现为缺陷。

## 1. 方案结论

保留进程内 Pi SDK 作为唯一执行路径，按能力选择性吸收 [`gotgenes/pi-packages`](https://github.com/gotgenes/pi-packages) 与 [`tintinweb/pi-subagents`](https://github.com/tintinweb/pi-subagents) 的改进，分三个阶段交付，本期只做 A 与 B。

已确定的取舍：

- **不引入 RPC 后端。** 子代理已经通过官方 `createAgentSession()` 复用 Pi 的模型请求与工具执行，不存在“自行实现模型调用引擎”的问题。为“直接使用 Pi”重写为独立 `pi --mode rpc` 进程，收益不成立，还需补齐进程、消息与资源生命周期管理。需要强制终止或故障隔离时另行决策。
- **按需加载内置扩展，不全量铺开。** 采用 gotgenes 的工具驱动策略，不照搬 tintinweb 为子会话加载全部内置扩展、连接全部 MCP 服务的方式。
- **冷恢复先限定同一父会话。** 不为恢复功能升级整套生命周期记录协议，也不照搬上游“父会话分叉后沿用原代理 ID”的策略。
- **保持本地配置优先级与预算语义。** 代理定义中的模型、思考等级优先于调用参数；轮次与时长预算只能收紧，不能放宽。
- **暂缓扩大职责。** 工作流、定时调度、嵌套代理、FleetView 与内置 worktree 自动保存分支都不随基础修复引入。

## 2. 目标与非目标

目标是让一次子代理执行更可靠、更容易判断成败，并在内存会话释放或重载后仍能找回并继续已有对话。

本轮不包含：

- 用上游 HEAD 覆盖本地实现，或整体替换本地生命周期记录。
- 跨父会话分叉的自动恢复，以及多实例同时续写同一子会话。
- 自动创建 Git 工作树、自动保存分支或自动提交。
- 父子主动通信工具（`ask_parent` / `notify_parent`）的完整语义设计。
- 第二套终端渲染器、任务管理仪表盘或全局会话数据库。

## 3. 现状与限制

| 方面 | 当前实现与影响 |
|---|---|
| 执行引擎 | 通过 `createAgentSession()` 创建进程内子会话，使用 `AgentSession.prompt()`、`steer()`、`abort()`；未自行实现模型请求层。 |
| 内置扩展 | 创建流程在 `session.bindExtensions({})` 中绑定资源加载器解析出的扩展，没有按代理工具清单选择 MCP、`tool_search`、`codemode` 的路径。 |
| 提示词 | 父提示词与子会话各自的系统提示分别组装；父环境说明（工具、技能、cwd）与子会话实际环境不天然同步，存在重复或过时的可能（待验证）。 |
| 默认思考等级 | 已有代理定义与调用参数的解析，但未补齐“两者都未指定时继承父会话实际 thinking”的链路。 |
| 取消与清理 | `InvocationControl` 使用协作式 abort 与有界等待；超时或取消返回不保证不响应 `AbortSignal` 的底层工具已经停止。 |
| resume | 依赖内存中保留的活会话；`releaseSession()` 之后记录与结果仍在，但不能再 resume。 |
| 父上下文继承 | `buildParentContext()` 拼接 user/assistant 文本与压缩摘要，跳过工具结果和非文本内容，不是结构化 fork。 |
| 生命周期记录 | 生产端为 v3，含 `invocationKind`、`invocationSource`、`invocationIndex` 与逐调用/累计指标；`pi-task-efficiency` 兼容读取 v2 与 v3。 |

## 4. 阶段 A：基础一致性与结果可信度

主要参考 gotgenes，涉及会话初始化、父状态快照、提示词与收尾判定。

| 项 | 调整内容 | 边界 |
|---|---|---|
| A1 内置扩展初始化 | 按代理实际声明的工具加载对应内置扩展，并核对声明的能力是否真实可用。 | 保留用户禁用项与扩展排除配置；缺失能力不得静默忽略，也不得为此扩大工具集合。 |
| A2 提示词分层 | 区分应继承的身份与规则，与 Pi 自动生成的工具、技能、cwd 等会话环境；后者按子会话实际环境重新生成。 | 只识别和替换 Pi 自身生成的区块，不按标题或位置粗暴截断；不得误删用户规则与项目规则。 |
| A3 跨目录项目规则 | 子代理工作目录变化时，按该目录解析适用的项目规则与资源路径。 | 与 A2 一并处理，但分别验证提示词内容与目录解析；共享用户级规则机制不变。 |
| A4 默认思考等级继承 | 代理定义与调用参数都未指定时，显式继承父会话实际 thinking。 | 不改变现有模型与预算优先级；固定思考等级的专用代理不受影响。 |
| A5 模型错误判定 | 依据最终模型消息及其后续重试状态判定成败，避免把失败报告为空成功，或让已成功的重试残留旧错误。 | 不把所有空回答一律判为失败；具体判定点待验证后确定。 |
| A6 取消与迟到结果 | 补齐真正启动前的取消检查，隔离旧调用的迟到结果，收尾阶段明确标识未确认停止的情况。 | 仍为协作式取消；不得把“调用方已返回”表述为“底层执行已停止”。 |
| A7 信任与能力限制传递 | 把既有项目信任决策、工具范围与扩展排除显式传到各创建路径。 | 只修既有机制接线，不新增权限引擎；工具列表不是操作系统沙箱。 |

## 5. 阶段 B：持久化查询与冷恢复

主要参考 tintinweb 的恢复机制，按本地记录与统计契约重新适配。

### 5.1 统一查找顺序

结果查询、会话查看器与恢复入口应使用同一套定位规则：

```text
当前内存记录 → 当前父会话分支中的合法持久化记录 → 按子会话身份定位 Pi 会话文件
```

首期继续使用现有 agent ID，不同时引入上游整套命名与寻址机制。

### 5.2 身份约束

`pi-task-efficiency` 的消费端要求一个代理 ID 对应一个子会话 ID，并按“代理 ID + 调用序号”去重。因此本期冷恢复保持原代理 ID、原子会话 ID，只续增调用序号；父会话分叉后不沿用原代理 ID 自动创建另一段子会话。

这项约束是本期不升级记录协议的直接原因。跨分叉恢复需要先单独设计来源关系、身份与统计归属。

### 5.3 恢复条件

| 情况 | 本期行为 |
|---|---|
| 内存释放、历史完整 | 允许恢复，同一父会话下重新打开原对话。 |
| 重启后回到原父会话 | 确认原实例已退出、记录完整且其余条件满足后恢复。 |
| 仍在运行或清理中 | 拒绝重复恢复。 |
| 文件丢失、记录不一致 | 不自动恢复，也不伪造缺失的调用数据。 |
| 原工作树或目录不存在 | 不自动恢复，不切回主目录，不新建工作树。 |
| 原角色被禁用或删除 | 不自动恢复，不降级为通用角色。 |
| 角色工具范围已收紧 | 按当前仍启用的定义加载，不恢复已失效的能力。 |

### 5.4 恢复语义

- 复用 Pi 标准会话打开能力加载历史对话，再发出新一轮任务。
- 本次调用的 usage、工具次数与轮次从零计；累计值从可信历史继续，调用序号续增。
- 不重放旧完成事件与旧通知，不重复拼接父上下文。
- 每次恢复重新应用当前预算上限。
- 历史信息不足时保持可读，但拒绝自动续跑。

冷恢复恢复的是对话，不是被中断工具的执行现场。

## 6. 阶段 C：异步使用体验

在 A、B 稳定后独立交付，避免同时改动初始化、持久化与调度。

| 项 | 调整内容 |
|---|---|
| C1 后台 resume | 恢复可选择前台或后台；后台恢复进入现有并发队列，重复恢复被拒绝。 |
| C2 前台恢复进度 | 前台恢复订阅并传递当前调用的进展更新，完成后仍返回最终结果。 |
| C3 查询等待期限 | 结果查询增加独立等待期限；到期返回“仍在运行”与当前进展，不修改任务执行预算。 |
| C4 当前活动与最近进展 | 统一提供当前活动、已用轮次与距最近进展的时间，只报告已观察到的状态。 |
| C5 工具名称兼容 | 增加明确有限的别名与大小写兼容；零匹配时给出提示，不静默忽略。 |

`ask_parent` / `notify_parent` 仍为后续候选，需先明确父代理何时回应、等待是否占预算、恢复后未处理消息如何处理。

## 7. 维持不变的边界

- 生命周期记录继续为 v3，历史 v2/v3 仍可读取；未知版本显式报告不支持。
- 工具名、服务身份、公开事件与默认执行方式保持稳定。
- 父会话保存生命周期记录，子会话保存 Pi 对话文件，不新增第三套会话存储。
- 会话查看器保持只读，不新增接管、恢复或停止操作。
- `inherit_context` 仍为文本与摘要拼接，不表述为完整结构化分叉。

## 8. 验收与实施顺序

实施顺序为 A → B1（持久化查询）→ B2（同父会话冷恢复）→ C，每一步可独立验收。

实施后应能证明：

- 声明的工具真正加载，禁用项有效；提示词与技能路径匹配实际目录；未指定 thinking 时按规则继承。
- 普通模型错误不被记为成功，成功重试不残留旧失败；空输出本身不被等同于失败。
- 取消或超时后旧调用不覆盖新调用，返回信息不虚报强制终止。
- 回收或重载后结果可查；同父会话满足条件时可续聊；文件或目录缺失时明确拒绝。
- 调用序号连续、统计不重复累计，历史记录继续可读。

局部变更运行相关包的类型检查、静态检查与测试；涉及跨包记录与统计时执行 `npm run test:contracts` 与根 `npm run verify`。生命周期与冷恢复部分需要独立审查。新增 API 依赖的最低 Pi 版本须按实际可用性核实后写入支持声明，不自动升级宿主或仓库 SDK。

## 9. 来源与同步要求

- 迁入基线与许可见 [UPSTREAM.md](../../packages/pi-subagents/UPSTREAM.md)：`@gotgenes/pi-subagents@19.3.4`，标签 `pi-subagents-v19.3.4`，MIT。
- 本方案核对的稳定版本：gotgenes `25.0.5`、tintinweb `0.23.1`；两者仍使用进程内 `createAgentSession()`，其跨扩展 RPC 指 `pi.events` 消息协议，不是独立进程。
- 同步时必须重新核对来源提交、许可证、实际差异与本地契约，逐项记录实际移植的提交与本地适配，不得用上游最新 HEAD 覆盖本地实现，也不把选择性移植表述为“已完整同步到最新版”。
