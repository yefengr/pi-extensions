# 子代理扩展上游改进同步方案

状态：A、B1、B2 与 C1–C5 均已完成本轮验收，A/B 基线提交为 `57cd867`。子代理包 81 文件、1470 项测试和 25 项跨包契约测试通过，相关类型与静态检查、外部消费者公开类型、文档链接及根 `verify` 均通过。C 已完成异模型族独立审查，无 P0–P3 finding；审查后冻结源码无漂移。本轮本地验收在 macOS 完成，Windows 客户端验证待在目标机器执行。本文保留实施前基线与设计约束，实际可用边界见[包说明](../../packages/pi-subagents/README.md#resuming-a-persisted-session)。

## 1. 方案结论

保留进程内 Pi SDK 作为唯一执行路径，按能力选择性吸收 [`gotgenes/pi-packages`](https://github.com/gotgenes/pi-packages) 与 [`tintinweb/pi-subagents`](https://github.com/tintinweb/pi-subagents) 的改进，按 A、B、C 三个阶段交付。

已确定的取舍：

- **不引入 RPC 后端。** 子代理已经通过官方 `createAgentSession()` 复用 Pi 的模型请求与工具执行，不存在“自行实现模型调用引擎”的问题。为“直接使用 Pi”重写为独立 `pi --mode rpc` 进程，收益不成立，还需补齐进程、消息与资源生命周期管理。需要强制终止或故障隔离时另行决策。
- **按需加载内置扩展，不全量铺开。** 采用 gotgenes 的工具驱动策略，不照搬 tintinweb 为子会话加载全部内置扩展、连接全部 MCP 服务的方式。
- **冷恢复先限定同一父会话。** 不为恢复功能升级整套生命周期记录协议，也不照搬上游“父会话分叉后沿用原代理 ID”的策略。
- **保持本地配置优先级与预算语义。** 代理定义中的模型、思考等级优先于调用参数；轮次与时长预算只能收紧，不能放宽。
- **暂缓扩大职责。** 工作流、定时调度、嵌套代理、FleetView 与内置 worktree 自动保存分支都不随基础修复引入。

## 2. 目标与非目标

目标是让一次子代理执行更可靠、更容易判断成败，并在内存会话释放或重载后仍能找回并继续已有对话。

本轮不包含：

- 用上游 HEAD 覆盖本地实现，或整体替换本地生命周期记录。
- 跨父会话分叉的自动恢复，以及多实例同时续写同一子会话。
- 自动创建 Git 工作树、自动保存分支或自动提交。
- 父子主动通信工具（`ask_parent` / `notify_parent`）的完整语义设计。
- 第二套终端渲染器、任务管理仪表盘或全局会话数据库。

## 3. 实施前基线与限制

| 方面 | 实施前实现与影响 |
|---|---|
| 执行引擎 | 通过 `createAgentSession()` 创建进程内子会话，使用 `AgentSession.prompt()`、`steer()`、`abort()`；未自行实现模型请求层。 |
| 内置扩展 | 创建流程在 `session.bindExtensions({})` 中绑定资源加载器解析出的扩展，没有按代理工具清单选择 MCP、`tool_search`、`codemode` 的路径。 |
| 提示词 | 父提示词与子会话各自的系统提示分别组装；父环境说明（工具、技能、cwd）与子会话实际环境不天然同步，存在重复或过时的可能（待验证）。 |
| 默认思考等级 | 已有代理定义与调用参数的解析，但未补齐“两者都未指定时继承父会话实际 thinking”的链路。 |
| 取消与清理 | `InvocationControl` 使用协作式 abort 与有界等待；超时或取消返回不保证不响应 `AbortSignal` 的底层工具已经停止。 |
| resume | 依赖内存中保留的活会话；`releaseSession()` 之后记录与结果仍在，但不能再 resume。 |
| 父上下文继承 | `buildParentContext()` 拼接 user/assistant 文本与压缩摘要，跳过工具结果和非文本内容，不是结构化 fork。 |
| 生命周期记录 | 生产端为 v3，含 `invocationKind`、`invocationSource`、`invocationIndex` 与逐调用/累计指标；`pi-task-efficiency` 兼容读取 v2 与 v3。 |
| 持久化时机 | `subagents:record` 在调用终态写入父会话；开始事件仅在内存广播。进程中途退出时，子会话可能已有新内容，父会话却没有对应终态，不能只取最后一条成功记录恢复。 |
| 标准会话打开 | SDK 提供 `SessionManager.open()`，但对缺失或空文件可能初始化新会话，打开旧格式还可能触发迁移；它本身不负责本方案所需的占用排他与历史完整性检查。 |

## 4. 阶段 A：基础一致性与结果可信度

主要参考 gotgenes，涉及会话初始化、父状态快照、提示词与收尾判定。

| 项 | 调整内容 | 边界 |
|---|---|---|
| A1 内置扩展初始化 | 按代理实际声明的工具加载对应内置扩展，并核对声明的能力是否真实可用。 | 保留用户禁用项与扩展排除配置；缺失能力不得静默忽略，也不得为此扩大工具集合。 |
| A2 提示词分层 | 区分应继承的身份与规则，与 Pi 自动生成的工具、技能、cwd 等会话环境；后者按子会话实际环境重新生成。 | 只识别和替换 Pi 自身生成的区块，不按标题或位置粗暴截断；不得误删用户规则与项目规则。 |
| A3 跨目录项目规则 | 子代理工作目录变化时，按该目录解析适用的项目规则与资源路径。 | 与 A2 一并处理，但分别验证提示词内容与目录解析；共享用户级规则机制不变。 |
| A4 默认思考等级继承 | 代理定义与调用参数都未指定时，显式继承父会话实际 thinking。 | 不改变现有模型与预算优先级；固定思考等级的专用代理不受影响。 |
| A5 模型错误判定 | 依据最终模型消息及其后续重试状态判定成败，避免把失败报告为空成功，或让已成功的重试残留旧错误。 | 仅判定本次调用，覆盖自动重试与无新文本；不把所有空回答一律判为失败。 |
| A6 取消与迟到结果 | 补齐真正启动前的取消检查，隔离旧调用的迟到结果，收尾阶段明确标识未确认停止的情况。 | 仍为协作式取消；不得把“调用方已返回”表述为“底层执行已停止”。 |
| A7 信任与能力限制传递 | 把既有项目信任决策、工具范围与扩展排除显式传到各创建路径。 | 只修既有机制接线，不新增权限引擎；工具列表不是操作系统沙箱。 |

### 4.1 提示词来源与目录规则

A2、A3 按来源组装提示词，不从父提示词字符串中搜索标题后截断。父状态快照应同时保留可核验的结构化构建选项、适用目录与实际 thinking；`getSystemPrompt()` 返回的完整文本用于比对，不能替代来源信息。

| 来源 | 子会话处理 |
|---|---|
| 用户自定义身份、通用约定与追加指令 | 保留原文及来源；自定义内容中恰好出现 `<tools>`、`<skills>`、`cwd` 等字样，不视为自动生成块。 |
| Pi 根据工具生成的说明、工具规则与运行环境 | 用子会话实际工具及目录重新生成；工具限制同时在注册与执行路径生效。 |
| `AGENTS.md` 等项目规则 | 通过子目录的标准资源发现重新解析，以规范化路径去重；共享用户级规则保留一次，父目录独有且不再适用的项目规则不带入。 |
| 技能清单、文件路径与 Pi 文档路径 | 依据子会话实际资源重新生成，保留 SDK 对资源来源和信任的处理。 |
| 扩展提供的额外区块 | 按来源保留；重新绑定的扩展自行生成其环境内容，不能仅因区块名称相似就删除。 |

优先复用 SDK 的 `BuildSystemPromptOptions`、`before_agent_start.systemPromptOptions` 与资源加载器。普通工具的上下文只有完整提示词文本，不能假定它也有命令上下文的 `getSystemPromptOptions()`。若从事件捕获选项，须覆盖后续处理器修改，并在派发时核对快照与当前有效提示词；历史系统消息只能用于交叉核对，不能证明本轮尚未发送的配置。

`forceSystemPrompt`、旧宿主缺少结构化接口、或扩展使快照与有效提示词不一致时，视为来源不透明。此时不做字符串猜测或宣称已消除环境冲突：不能可靠重建的调用在创建子会话前明确拒绝，并给出缺失的能力；不得静默删规则、退回通用身份或自动升级 SDK。实现前用兼容性验证确定最低支持版本。

`prompt_mode: append/replace` 的既有身份继承及代理指令包装语义保持不变；重新加载目录规则不能意外增加一份 `APPEND_SYSTEM.md`。同目录、跨目录和两种模式分别验收。

### 4.2 初始化、结果与取消的判定点

- 工具、扩展、信任和目录在统一初始化入口解析，工具调用入口与公开服务入口共用。扩展绑定后、真正请求模型前，核对声明能力；缺失或被禁用的能力明确报错，不扩大工具清单补齐。
- 同目录继承既有信任决策；换目录时按目标项目的既有信任机制解析，不能仅凭父项目已受信任就启用另一项目的资源。首次创建与冷恢复应用同一规则。
- thinking 优先级固定为“当前代理定义 → 本次参数 → 父会话派发时的实际值”，排队期间不读取漂移后的父状态。模型与轮次、时长预算继续使用现有解析规则。
- A5 在本次 `prompt()` 及自动重试结算后，检查本次调用范围内的最终模型消息、错误信息与取消状态。成功重试清除先前失败；没有异常抛出不等于成功；空文本本身不等于失败，也不得回取上一轮回答冒充本轮结果。
- A6 在排队出列、工作区准备、会话创建和发出 prompt 前检查取消。超时或取消可以有界返回，但在实际调用与清理未结束前，继续保留占用状态；旧调用的迟到事件不得修改新调用结果或统计。B2 依赖这一停止确认边界。

## 5. 阶段 B：持久化查询与冷恢复

主要参考 tintinweb 的恢复机制，按本地记录与统计契约重新适配。B1 先交付只读查找，B2 再接入执行；能查看历史不代表满足续跑条件。

### 5.1 统一查找顺序

结果查询、会话查看器与恢复入口共用一套定位规则：

```text
当前内存记录 → 当前父会话分支中的合法持久化记录 → 按已确认的子会话身份定位 Pi 会话文件
```

- 内存中仍在运行、清理中或身份冲突时直接返回该状态，不绕过它去磁盘创建第二个执行实例。
- 持久化记录从父会话当前分支读取，不将同文件其他分支的调用混入；首期继续使用现有 agent ID。
- `outputFile` 只是候选路径，需核对会话头的子会话 ID、原父会话关联和目录归属。路径失效时，仅在该父会话已有的子会话目录内按 ID 查找；零个候选报告缺失，多个候选报告冲突，不选最近文件代替。
- B1 使用只读解析，不通过 `SessionManager.open()` 实现查询。读取不启动模型、绑定扩展、迁移文件、建立运行项或重发通知。损坏文件仅展示可确认的内容，并标明不完整。

### 5.2 身份与父分支约束

`pi-task-efficiency` 要求同一代理 ID 的子会话 ID 与代理类型一致，并以“代理 ID + 调用序号”区分调用。本期冷恢复保持原代理 ID、原子会话 ID 和原类型；下一次调用序号只能是可信历史末次序号加一。

恢复还必须确认原父会话文件与 ID，且恢复检查点引用的父终态记录仍在当前分支。不同父会话、分支缺少原记录、调用序号重复或缺失、同一代理映射到不同子会话时，只允许查看可确认的历史。不能通过创建新子会话后复用旧代理 ID 绕过这些限制。

这项约束是本期不升级生命周期记录协议的直接原因。跨父会话分叉恢复需要先单独设计来源关系、身份与统计归属。

### 5.3 恢复条件

以下条件需同时满足：身份与父分支一致、历史完整、原目录存在、当前角色与信任允许、已取得独占使用权。

| 情况 | 本期行为 |
|---|---|
| 内存释放，具备有效关闭检查点 | 校验通过后允许重新打开原对话。 |
| 正常退出后重启并回到原父会话 | 按同一套检查点与占用规则恢复，不仅凭“已重启”判断安全。 |
| 仍在运行、清理中，或留有未解除的占用标记 | 拒绝重复恢复；调用方已返回或 PID 不存在均不足以自动解锁。 |
| 中途崩溃，子会话尾部缺少对应父终态或关闭检查点 | 历史保持可读，拒绝自动续跑。 |
| 历史 v2/v3 记录缺少关闭检查点 | 保留历史读取能力；本期不自动补点或迁移成可恢复状态。 |
| 文件丢失、空文件、解析损坏、身份或统计不一致 | 不调用会话打开接口，不新建替代会话，不伪造缺失数据。 |
| 原工作树或目录不存在 | 不切回主目录，不新建工作树；历史仍可查看。 |
| 原角色被禁用或删除 | 拒绝恢复，不降级为通用角色。 |
| 角色工具范围已收紧，或目标项目不再受信任 | 按当前定义与信任加载；无法满足声明能力时拒绝，不恢复已失效能力。 |
| 上次为取消或超时 | 终态本身不足以恢复；只有实际执行、清理均结束并形成有效关闭检查点后才进入普通校验。 |

### 5.4 占用与停止确认

首期使用与子会话文件相邻的占用标记协调本扩展的本机实例，按规范化后的真实目录与子会话 ID 确定唯一位置，不能因相对路径或符号链接绕过。通过文件系统原子排他创建取得使用权，不采用“先检查不存在，再创建”的方式。标记只记录所有者随机令牌及诊断所需的进程信息，不存放对话、结果或统计。

占用范围覆盖子会话的整个存活期：首次创建、内存续聊、冷恢复、迟到任务和会话清理都经过同一入口。持有活会话的实例可以串行续聊自己的会话；其他实例必须拒绝。内存记录被回收或移除，不等于占用已经解除。

释放占用必须同时确认：没有尚未结束的准备、创建或 turn loop，没有待结算的重试、排队消息或工具调用，会话和工作区清理已完成，且关闭检查点已成功写入。关闭处理器超时、底层操作不响应取消、持久化失败或停止状态不明时保留占用标记，禁止冷恢复。清理只能删除令牌仍属于自己的标记。

进程崩溃留下的标记本期不自动回收，也不以超时、文件 mtime 或 PID 探测代替停止证明。异常解锁与跨主机共享会话不在本期范围；该机制仅协调遵循本扩展入口的实例，不承诺阻止其他程序直接打开会话文件。旧数据没有占用标记，也必须通过关闭检查点校验，不能据此认定已安全释放。

### 5.5 历史完整性与关闭检查点

现有 v3 终态记录不足以证明子会话在最后一条记录之后没有继续执行。B2 因此在原子会话中追加一个私有关闭检查点，复用 Pi 的 `custom` entry；它不进入模型上下文、不替代父会话的 `subagents:record`，也不新增公共生命周期事件。

检查点只保存恢复关联信息：私有格式版本、原父会话文件与 ID、对应父终态记录的 entry ID、代理 ID 与类型、子会话 ID、末次已结算调用序号。它在子会话树中的 `parentId` 标识关闭前的历史边界，不重复保存结果或 usage。

写入顺序为：**本次调用实际结算 → 父会话 v3 终态写入成功 → 会话与相关资源清理完成 → 在原子会话末尾追加关闭检查点 → 释放占用**。有界清理已返回但未确认结束时，不写检查点、不释放占用。检查点通过原 `SessionManager` 的记录能力写入，不能为收尾重新打开另一份可执行会话。

冷恢复取得占用后、调用 `SessionManager.open()` 前，重新只读核验：

1. 文件是非空且受支持的完整 Pi JSONL；会话头、条目 ID 与父子关系有效，原 cwd 存在。不能容忍坏行后再把解析出的有效前缀当完整历史。
2. 关闭检查点是文件最终条目并位于选定子分支末端；其关联与当前父分支中的终态记录一致。检查点之后有任何新条目、子分支被改写或未知检查点版本，都拒绝续跑。
3. 父分支内同一代理的调用序号从 fresh 到末次连续、唯一，子会话和类型不变，调用窗口不重叠。各次及累计 usage、工具数和轮次须能与子历史对应；缺失数据不按零补齐。
4. 对话没有未完成工具调用、未归属的新一轮输入或未结算尾部；若 SDK 打开操作会迁移格式或初始化替代会话，则本期不自动恢复该文件。

任一检查失败，只返回具体拒绝原因与可读历史，不截断尾部、不重写旧记录、不补造终态。旧数据继续可查，但完整的 v3 终态记录本身不自动等于可恢复数据。

### 5.6 恢复执行与统计

1. 只读定位候选，执行不依赖占用的初步检查；预检失败不创建运行项、不分配新调用序号，也不产生新的执行 usage。
2. 取得占用后重读候选，执行完整校验，防止校验与打开之间被另一实例修改。随后用 `SessionManager.open()` 打开已确认的原文件，并核对子会话 ID 与原 cwd 未变；不调用创建、fork 或 continue-recent 路径兜底。
3. 在原 cwd 下按 A 阶段的统一入口应用当前角色、信任、扩展排除和工具范围。模型与 thinking 按当前定义及调用规则解析，历史配置不能恢复已失效能力；轮次、时长同时受当前规则和原任务可证明的上限约束。
4. 实际接纳本次执行时，调用序号递增一次，本次 usage、工具数和轮次从零计；累计值取已校验的历史，不能再次把整份会话统计叠加进去。不重复拼接父上下文。
5. 新调用结束后仅为本次调用产生正常 v3 终态记录与对应事件；历史读取与恢复初始化不重放旧完成事件、旧通知或旧工具调用。再次释放时按 5.5 写入新的关闭检查点。

取得占用后的预检拒绝，若尚未打开 SDK 会话、未改写原文件或启动工作，只撤销本次令牌对应的占用，不需要补写新检查点。初始化已经开始后发生错误，则先完成相应清理；文件已改变或停止状态不明时保留不可恢复状态，不为再次尝试强行解锁。

冷恢复恢复的是对话，不是被中断工具的执行现场。B2 首期以前台方式交付；C1、C2 在相同身份、占用与检查点约束下增加后台续聊与前台进度。

## 6. 阶段 C：异步使用体验

在 A、B 稳定后独立交付，避免同时改动初始化、持久化与调度。

| 项 | 调整内容 |
|---|---|
| C1 后台 resume | 已实现。仅显式 `run_in_background: true` 选择后台；live/cold 恢复共用原并发队列与排队期限，接纳时预留调用、拒绝重复恢复，旧回调按调用序号隔离。 |
| C2 前台恢复进度 | 已实现。fresh/live/cold 前台执行共用进度更新与 spinner，完成后返回真实结果；更新回调失败不改执行结果，结束时清理定时器。 |
| C3 查询等待期限 | 已实现。`timeout_seconds` 为 1–3600 秒整数，等待默认 60 秒；到期或查询中断只结束查询，不取消任务、修改执行预算或消费未完成结果。 |
| C4 当前活动与最近进展 | 已实现。查询、工具、widget 与 service 复用当前活动、本次轮次及已观察进度时间；未知时间不补零，不按间隔推断 stalled，进度不写入公共 v3 记录。 |
| C5 工具名称兼容 | 已实现。SDK 接纳前处理有限别名与唯一大小写匹配，精确注册名优先、歧义拒绝；未知名称保留给绑定后零匹配检查，不扩大工具权限。 |

后台续聊在排队取消或超时时可复用原子会话却没有新对话回合。统计消费端仅在 v3 后台 resume、取消或排队超时，且本次回合、工具数与全部用量均明确为零时接受空执行窗口；v2 缺失计数不推断为零，缺失或损坏 transcript、非零指标与其他空窗口仍报告不完整。跨包验证使用生产生命周期记录的序列化输出。

`ask_parent` / `notify_parent` 仍为后续候选，需先明确父代理何时回应、等待是否占预算、恢复后未处理消息如何处理。

## 7. 维持不变的边界

- 生命周期记录继续为 v3，历史 v2/v3 仍可读取；未知版本显式报告不支持。
- 工具名、服务身份、公开事件与默认执行方式保持稳定。
- 父会话保存生命周期记录，子会话保存 Pi 对话与私有关闭检查点，不新增第三套会话存储。相邻占用标记只协调使用权，不保存另一份结果或统计。
- 会话查看器保持只读，不新增接管、恢复或停止操作。
- `inherit_context` 仍为文本与摘要拼接，不表述为完整结构化分叉。

## 8. 验收与实施顺序

实施顺序为 A → B1（持久化查询）→ B2（同父会话冷恢复）→ C，每一步独立验收；前一步未满足契约时不靠后续功能掩盖。

### 8.1 分步交付

| 步骤 | 交付与进入下一步的条件 |
|---|---|
| A | 统一创建入口、父状态快照和本次调用结果判定；工具调用与服务入口均覆盖，取消后未结束的操作仍可追踪。A2/A3 的结构化提示词来源和最低 SDK 版本先验证，再实施重组。 |
| B1 | 结果查询与只读查看器共用分支定位及文件解析；内存释放和重载后可查，失败时无模型、扩展初始化或文件迁移。 |
| B2 | 首次创建与所有续聊路径先纳入统一占用管理，再实现关闭检查点、历史校验和标准会话打开；缺一项不开放冷恢复。原目录、角色、预算和统计契约同时验收。 |
| C | 在 A/B 稳定后单独处理调度、进度与等待体验，不改变 B2 的身份、占用和统计约束。 |

### 8.2 必须覆盖的验证场景

| 场景 | 预期结果 |
|---|---|
| 声明 MCP、`tool_search` 或 `codemode`；对应扩展被禁用或排除 | 所需能力实际加载；被禁用时明确拒绝，不扩大工具集合。 |
| 同目录及跨目录，append/replace，规则正文含与 Pi 区块相同的标题或标签 | 用户规则不丢失、不重复；适用的项目规则与技能路径匹配实际 cwd。 |
| 提示词来源不透明、后续处理器修改、缺少所需 SDK 接口 | 明确报告不支持；不猜测切分、不启动受影响的子会话。 |
| thinking 均未指定、profile 固定值、参数试图覆盖 profile、排队后父状态改变 | 依次符合既定优先级及派发快照；模型和预算原规则不变。 |
| 普通模型错误、失败后自动重试成功、合法空文本、续聊没有新文本 | 错误不记成功，重试成功不残留失败，空文本不误判或借用旧回答。 |
| 启动前取消、排队取消、创建迟到、工具忽略取消、关闭处理器超时 | 不执行已取消的新工作；迟到状态不覆盖新调用；未确认结束时不释放占用、不写关闭检查点。 |
| 回收后查询、正常关闭后重启查询、同父会话冷恢复 | 查询无执行副作用；有有效检查点且全部条件满足时，原 ID、子会话与 cwd 保持一致。 |
| 两个实例同时恢复、已有活会话、清理未完成、崩溃残留标记 | 最多一个实例取得使用权，其余拒绝；不按 PID 或时长自动解锁。 |
| 父会话更换、当前分支缺锚点、子分支变化、重复或缺失调用序号 | 拒绝续跑，不合并其他分支的数据。 |
| 子会话有新增尾部但父终态缺失、检查点缺失或版本未知、坏行或半行 | 只展示可确认的历史；不修剪、补点或补造成功记录。 |
| 文件缺失或为空、旧格式需要迁移、原目录消失、角色禁用、信任或工具收紧 | 不初始化替代会话、不回退目录或角色；查询仍按可用历史返回。 |
| 多次 fresh/resume、冷恢复后再次回收、历史 v2/v3 查询 | 调用序号连续，逐调用与累计指标一致且不重复累计，私有检查点不改变统计与旧记录读取。 |
| live/cold 后台续聊排队、重复恢复、取消及旧排队回调迟到 | 只接纳一次新调用，排队不启动 prompt 或消耗执行预算；旧回调不操作后续调用。合法零执行窗口不重复累计旧对话。 |
| 前台进度、查询到期或中断、更新回调异常 | 前台仍返回真实结果；查询期限独立于执行期限，active 结果不被消费；定时器与监听器均清理。 |
| 新调用、无观察、终态迟到事件、最近进度与窄屏 | 本次进度重置，只报告实际事件；未知时间不伪造，不推断 stalled，状态行不超出终端宽度。 |
| 有限别名、精确名冲突、模糊大小写、wildcard、未知与空名称 | 接纳前规范化、精确名优先、歧义明确拒绝；绑定后保留零匹配检查，不扩大声明能力。 |

文档变更运行 `npm run check:docs` 和 `git diff --check`。后续代码实施时，局部变更运行相关包的类型检查、静态检查与测试；B2 涉及跨包记录解释与统计，执行 `npm run test:contracts` 与根 `npm run verify`。契约测试使用真实生产序列化输出，并加入关闭检查点与异常尾部，验证消费端不重复计数。

生命周期与冷恢复实现需要独立审查，覆盖占用竞态、停止确认、父子分支一致性、统计和旧数据兼容。真实 SDK smoke 至少验证一次“创建 → 完成 → 释放 → 重开 → 续聊”，并验证缺失文件不会被打开成新会话；不以模拟 SDK 的单元测试替代该验证。新增 API 依赖的最低 Pi 版本按实际可用性核实后写入支持声明，不自动升级宿主或仓库 SDK。

### 8.3 已实现的约束与支持基线

- 按公开结构化选项继承身份和显式用户区块，重建子会话环境；SDK 把 APPEND 来源压成正文时，跨目录且父子内容不同的调用明确拒绝，不猜测项目作用域。
- 同目录继承父信任，跨目录只读查询目标既有信任；不把父信任扩散到另一个项目。
- 关闭检查点记录原 cwd、父终态条目 ID、调用序号及树边界；父终态须从磁盘读回。SDK 的内存条目不视为已落盘证明。
- 本机占用覆盖活会话和未确认停止的迟到工作；历史缺检查点、异常尾部、崩溃残留不自动修复。只读查询保留可确认的结果并标记不完整历史。
- 最低支持声明收敛为已验证的 Pi SDK `>=1.5.1`，未升级开发依赖或宿主 SDK。更早版本未获得此次实现的支持承诺。
