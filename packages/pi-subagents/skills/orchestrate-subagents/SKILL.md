# Orchestrate Pi Subagents

为 Pi 子代理及其项目或用户自定义 profile 提供通用编排协议。代理 profile 是稳定模型、工具、权限、职责和输出格式的真源；本技能只规定委派、证据交接、所有权、审查和生命周期收口，不承载领域业务规则。父 Agent 始终保留五项责任：需求与共享决策、契约与证据冻结、跨节点协调、finding 取舍与结果整合、最终验证与交付。子代理结果是待核验输入，不是项目事实真源；写作代理的产物也必须由父 Agent 核对事实与精确内容。

## 1. 核对能力并选择角色

派发前先确定本次角色（探索、诊断、实现、写作、审查或修复）及其所需能力，再把运行时实际发现且已启用的代理定义作为候选；候选以当前项目覆盖全局后的实际加载结果为准，不凭仓库文件存在或旧描述判断可用。先按本次角色与运行时描述筛选少量候选，再定向核对候选的实际定义，读取职责、模型、思考等级、工具权限、上下文来源和资源上限，并核验模型可用性；已核验且未变化的能力证据可复用，启用状态、模型可用性与职责匹配等易变状态在派发前重验，不全文重读所有定义。同时核对主 Agent 的有效模型与思考等级和候选能力，以判断委派净价值。未知字段标为 `unknown`，`expert`、`high` 等名称不是能力证据。代理定义中的 `model` 和 `thinking` 优先于调用参数或继承值。未知的关键能力不足以支持派发时不得猜测；无合格候选时由父 Agent 处理或返回最小缺口，不能擅自启用或新建 profile。任务的只读约束与工具 allowlist 不同，具备 bash 等权限不等于只读沙箱，本技能不新增强权限承诺。多角色 profile 只承担本次指定角色；诊断转为实现或修复前，由父 Agent 重新冻结角色、授权、写入范围和推荐实施思路，不得因代理具备编辑工具直接继续写入。能力证据和本次授权同时约束选择：简单任务优先成本适当且能力足够的候选，复杂已冻结任务选择相称的推理、实现与验证能力。默认实现与修复优先能力相称、成本适当的实现角色，复杂且方向明确的实现使用推理能力更高的实现角色；疑难根因诊断与纯事实定位分别交由诊断与探索角色，不把独立开放式契约调查交实现角色。独立审查的独立性按实际模型系谱判断：审查者必须未参与对应实现，且与实现者不属于同一模型族；模型族以实际模型系谱为准，不按 provider、profile 名或是否新建会话推断。覆盖不足、实际模型族不明或与实现者同族时，审查者返回 blocked，不以异族或新会话替代能力与覆盖证明。Agent 定义负责稳定能力与权限，领域 Skill 负责触发条件、项目真源和风险矩阵，不在两处重复维护业务规则。

| 角色 | 所需能力 | 负责 | 复核边界 | 停止点 |
|---|---|---|---|---|
| 探索 | 只读事实搜集、路径与关键词限定、证据定位 | 接收调查输入，只读建立带证据的事实候选和直接消费者范围 | 限定路径、关键词、候选数和下游用途，不把预设实现结论当事实 | 达到搜索停止条件 |
| 诊断 | 复现、假设验证、调用链与直接消费者分析 | 在冻结范围内定位根因并给出最小证据，默认只读 | 无预设修复结论，不把范围内的无匹配解释为全局不存在 | 假设验证收口或需要父 Agent 重新冻结 |
| 实现 | 契约消费、局部跨文件修改、有限重构、目标验证 | 消费冻结契约、推荐实施思路和写入白名单，只在冻结边界内修改并局部验证 | 只读编辑所需接口，不从零盘点；偏离推荐路线前先回传 | 事实冲突、推荐路线不可行或需要改变共享契约 |
| 写作 | 冻结事实落笔、人类可读结构、精准表达 | 把父 Agent 冻结的事实与文档结构写成人类可读正文，遵守冻结人类文档契约 | 只读指定参考，只改白名单文档，不新增结论或技术方案 | 正文完成或写作契约不足 |
| 审查 | 独立核验、风险矩阵覆盖、冻结产物比对 | 按父 Agent 给定的检查顺序覆盖冻结产物及风险矩阵 | 独立于实现者，只核验分配风险，不接收实现方案作为审查结论 | 矩阵完整覆盖 |
| 修复 | finding 收敛、原边界内修复 | 闭合父 Agent 已确认并聚合的 finding；优先使用仍可恢复且能力合格的原 owner，否则按需求重新选择 | 只处理 finding 涉及范围 | 原契约失效 |

单一路径、少量事实由主 Agent 直接核对；只有调查方向可独立、结果会被多个下游复用或能并行缩短关键路径时才委派探索角色。小型低歧义任务可合并探索与实现；实现与独立审查不得由同一代理承担。

面向人类且包含实质性说明正文的文档，按剩余写作工作与交接成本判断委派净价值；仍有较多结构组织、解释或表达工作、净价值为正，且事实、术语、结构和写入范围冻结后，才交给写作角色最终落笔。只有存在合格候选时才委派，无候选时按上文缺口规则处理。局部增量修改、已有完整正文后的少量调整和简单机械修改，可由主 Agent 完成，不因产物属于说明文档就强制委派。以模型或自动化流程为主要消费者的上下文、交接、证据、状态和临时执行文档仍由父 Agent 或原执行代理编写。

写作契约中的结构冻结是明确必要章节和调整权限，允许写作代理在该范围内组织提纲，不要求父 Agent 预写完整初稿。返回正文模式的写入范围为空，无需目标文件；成功交付完整正文，不能用状态表代替。写入文件模式才要求精确路径和创建或更新授权。正文写作方法可复用当前会话已发现的通用人类文档写作技能；父 Agent 将该技能的实际路径和必要参考纳入读取白名单，子任务直接写作与自查，不再执行宿主委派流程。未发现此类技能时，按冻结事实与结构直接落笔。

## 2. 判断委派价值并通过就绪门

每次 fresh spawn、resume 或新增 reviewer 前重新判断：

```text
委派净价值
= 并行或顺序执行收益
+ 专项能力、独立审查和上下文隔离收益
- 交接、等待、重复调查和父 Agent 核验成本
```

只有任务边界明确、代理能力足够、存在可核验产物，且本次调用会产生新价值时才委派。任务简单、契约未稳定、高歧义或高风险决策、所有权无法互斥、能力不足或核验成本抵消收益时不委派；不得只以“主 Agent 更强”为理由拒绝稳定、封闭且可核验的实现委派。

独立审查按风险触发：用户明确要求，或独立核验能显著降低共享契约、关键行为、权限或数据一致性风险时，委派审查角色。项目或领域技能明确要求独立审查时仍须执行；无合格候选时报告缺口，不以主 Agent 自查冒充独立审查。范围明确、风险低且已有充分验证的修改，可由主 Agent 复核，不因实现完成或涉及多个文件就自动增加审查节点。

每次派发前必须通过以下硬门；任一项未满足时先由主 Agent 补齐，不把缺口留给 steering：

1. 角色、目标、非目标和共享决策边界已经冻结，没有仍会改变结果的用户决策；写作任务还须冻结目标读者、文档目的、事实、术语、结构、禁写项和原样保留内容。
2. 当前工作目录、HEAD、工作区状态、用户授权和允许副作用已经核对。
3. 目标 Agent 定义已实际发现且处于启用状态，职责与本次角色匹配，有效模型及其可用性、思考等级、工具、上下文和最大轮次已确认。
4. 读取范围、直接消费者、互斥所有权以及写入任务的精确白名单已经冻结。
5. 已读取项目规定的命令真源，验证命令、执行目录、前置依赖和预期非零分支均可直接执行；不得派发后再纠正 cwd 或命令形式。
6. 前置输入、证据版本、失效条件和无需重复调查的事实已经交接。
7. 产物、软预算、搜索停止条件、验证和返回格式已经明确。
8. 实现与修复任务已经提供推荐实施思路，至少包含方案方向、执行顺序、必须复用、必须保持、不建议路线和偏离回传规则；任一项缺失时不得派发，也不得要求 worker 自行补造。

实现与修复任务的契约还须写明阻塞分类 `contract`、`evidence`、`environment`、`scope`、`capability`。子代理返回 blocked 或 failed 时先按该分类处理：契约或范围问题由父 Agent 重新冻结，环境问题由父 Agent 统一处理，根因未知交诊断角色，只有能力不足或已识别的复杂实现才升级到更高能力实现角色；不因 blocked/failed 本身或失败次数自动升级模型。

写入任务必须传入用户已有授权和精确写入白名单；扩大范围或副作用时停止。字段填写使用[任务契约模板](references/prompt-contract.md)。探索任务接收调查问题、范围和停止条件，不要求预设实现结论；诊断任务接收调查输入，同样不要求预设修复结论；reviewer 接收冻结产物、风险矩阵和检查顺序；写作代理接收冻结事实、目标读者、文档目的、章节结构与原样保留内容。探索、诊断、审查和写作任务不因缺少 worker 的推荐实施思路而阻塞。

## 3. 建立依赖、所有权与并行关系

按依赖关系拆分，不按文件数、表面工作量或预计耗时机械拆分。每个节点明确 role、owner、读取范围、互斥写入范围、前置输入、输出、停止条件和验证。

- 同一文件、目录或共享契约同时只能有一个写入 owner；父 Agent 不并发修改该范围。
- 有顺序依赖或共享状态时串行；输入、写入范围和验收均独立时才并行。
- 同一所有权范围的局部缺陷仅在原实现者仍可恢复且契约未失效时优先 resume；fresh 代理必须带来独立性、不同能力或不可复用上下文等新增价值。
- 同一冻结产物需要通用与项目专项审查时，优先由一个 fresh 审查角色 profile 顺序覆盖两阶段并输出去重报告；若领域 Skill 要求父 Agent 在阶段间做门禁，则阶段 A 返回后立即 resume 同一 reviewer 执行阶段 B。只有风险矩阵需要不同能力、权限或独立性时才拆成多个 reviewer。
- 多个 reviewer 必须检查互补风险，不能重复阅读相同产物却没有新增检查面。
- 实现节点的所有权盘点必须覆盖全部直接耦合文件，具体分类以[任务契约模板](references/prompt-contract.md)为准。共享文件必须有唯一 integration owner 和串行节点；任一直接耦合文件未归属时不得并行派发。

## 4. 冻结证据并向干净上下文交接

探索结果不得只留在会话中。派发依赖这些结论的 fresh 代理前，父 Agent 必须建立可直接消费、可定向复核的交接包。

交接项用两种维度标注：

- **状态**：`frozen` 可复用、`review` 需指定 reviewer 核验、`unresolved` 待父 Agent 决策、`disproved` 禁止继续采用。
- **生命周期**：`stable` 长期稳定、`snapshot` 绑定 diff/版本/时间、`volatile` 使用前重验。

关键事实至少包含 ID、结论、证据路径/符号/命令、适用范围、允许复核角色和失效条件。只有结论而无证据位置，不算冻结。证据复用不替代编辑前对目标位置的即时读取。

交接载体按复杂度选择：

- 单个下游、少量事实且不跨会话：内联到任务 prompt。
- 多下游、跨角色、证据密集或可能跨会话：在已获本地写入授权时使用 `.pi/tmp/<task>-evidence.md`。
- 需要任务恢复时，`.task-context.md` 只记录阶段、证据包路径、契约版本、阻塞和下一步，不复制证据正文。
- 未获临时文件写入授权时，将同等信息内联；不得省略交接。

父 Agent 核验子代理返回的新事实后才合并到交接包，并标记失效证据。冻结事实与当前证据冲突时，代理停止受影响工作，返回原事实、最小冲突证据、影响和最小替代方案；父 Agent 重新冻结前不得扩围或改变共享契约。

## 5. 约束调查、工具预算与停止条件

`max_turns`、软工具预算和搜索停止条件互补，不能相互替代。每份契约必须限定文件/目录、候选数量或关键词，并设置可观察停止条件，例如关键符号已定位、风险矩阵已覆盖或目标验证已通过。

代理 profile 已固定的只读/写入边界、禁止副作用和通用输出格式不在每次 prompt 中逐段复制；任务契约只补充本次目标、范围、权限、证据、命令和失效条件。主 Agent 仍须在自己的证据中记录本次调用的有效能力，不能因压缩 prompt 省略就绪门。

实现者默认复用冻结事实，不重新盘点 SDK、依赖树、项目结构或全局安装；reviewer 不从零重建架构模型。达到软预算检查点仍无法完成时，返回已用证据、缺失信息、最小扩围请求和不扩围风险，由父 Agent 决定追加预算、缩小目标或终止委派。具体预算起点见[任务契约模板](references/prompt-contract.md)。

路径不存在、命令不可用或公共环境阻塞时只返回一次最小证据，由父 Agent 统一处理；不要让多个代理重复探测同一环境问题。

## 6. 执行、审查与返工

- 只有独立且可验收的节点才使用 `run_in_background: true`；不为填满并发槽拆任务。
- 有依赖时先验收真实上游产物，再交接给下游；不以预期输出代替结果。
每次 fresh spawn 或 resume 都在父任务状态中保留最小生命周期记录；简单任务可内联，已有证据包或任务上下文时写入对应临时状态，不为此单独创建项目文档：

```text
agent_id:
role:
ownership:
status:
result_consumed:
follow_up:
resume_policy: immediate | fresh_later | none
```

子代理失败、超时、空返回或仅部分完成后，先核对真实终态、已产生产物、剩余工作和未覆盖风险，并按 `contract`、`evidence`、`environment`、`scope`、`capability` 分类阻塞原因；不按 blocked/failed 本身或失败次数自动升级模型。接手同一写入范围前，确认原 owner 已停止且没有未结束的写入，并检查已有局部文件。主 Agent 已有充分证据且能直接完成剩余工作时，由主 Agent 接手收口；仍需委派时，重新判断剩余任务的委派净价值与候选能力匹配，再决定 resume、fresh spawn 或更换代理，不因前一次调用失败就自动重新派发。明确要求的独立审查不得改由实现者自验替代；能力不足时报告缺口。

- 记录真实 agent ID；自然检查点再查询，不高频轮询或重复投递。
- 子代理进入终态并读取结果后，先聚合同一 owner 的 findings，再决定 `resume_policy`，不得把决定推迟到无关阶段之后。
- 共享契约未变化、原 owner 仍适合处理且修复可以立即开始时使用 `immediate`；在长测试、数据库 smoke、新一轮审查或用户等待前，一次性 resume 聚合后的 findings。同一 owner 的同一批 findings 最多 resume 一次。
- 后续处理仍需委派且需要跨过实质阶段、用户等待或较长间隔时使用 `fresh_later`；先冻结已消费结果和最小 finding 契约，后续通过委派就绪门后再 fresh spawn，不先试探旧 agent 是否仍可恢复。审查 finding 的关闭核对同样遵循该规则：修复链很短且 reviewer 仍可恢复时立即 resume，否则重新判断独立核验的需要与委派价值。
- 不依赖或猜测具体 session 保留时长。状态未知时只查询一次；resume 返回 released/not found 后不重试，按上述异常收口规则重新判断；仍需委派时按已冻结契约 fresh spawn，并记录运行时偏差。
- `steer` 只用于状态已确认仍为 `running` 的代理，且原因必须是用户新增约束、外部事实变化或冻结契约失效；命令、cwd、白名单和输出格式错误应在派发前消除。确需 steering 时合并为一次消息，避免制造多个未结算子回合。
- 子代理运行时，父 Agent 可整理证据、准备验收并完成不冲突的本地工作，但不得重复其调查或并发修改其所有权范围。只有这些工作已经耗尽且下游确实依赖结果时，才调用 `get_subagent_result(wait=true)`。
- 审查绑定冻结 diff、commit、文档版本或 pathspec；明确负责和排除的风险、已有验证及 finding 级别。低风险机械改动可由父 Agent 复核。
- 写作角色完成后，父 Agent 核对事实、术语、命令、路径、代码块、表格、链接和写入范围；除纠正事实或违反契约外，不把正文重新改回主 Agent 的文风。
- 父 Agent 核验、去重并聚合同一实现范围的 findings 后，仅在原实现者仍可恢复时 resume 一次；机械 finding 可改交满足所需能力、成本适当的轻量实现 profile，独立关闭核对不得由实现者承担。

遇到偏差先分类：不改变共享契约的局部命名、拆分和等价实现可由 worker 自行调整；证据表明推荐路线不可行或调整会影响共享契约时，worker 必须在继续编辑前返回原路线、最小冲突证据、影响和最小替代方案，由父 Agent 重新冻结。局部实现缺陷沿原契约修复；需求或证据推翻契约时暂停下游；环境问题由父 Agent 统一解决。重复返工时重新检查契约完整性、能力匹配、所有权、证据时效和剩余委派价值。

## 7. 验收、收口与能力边界

子代理统一按[任务契约模板](references/prompt-contract.md)中的“输出格式”段落返回。父 Agent 核验工作目录、角色、权限、所有权、证据版本、产物、验证、契约偏差、待决策项和剩余风险；写入产物进入统一 diff 审查和最终验证。

任务使用子代理时，在最终交付证据中核对以下编排指标；不满足时记录原因和对应成本，不为追求数字而牺牲正确性或独立审查：

- 对明确已跨阶段的 agent，试探性 `resume` 后得到 released/not found 的次数目标为 `0`。
- 每个 owner 对同一批聚合 findings 的 resume 次数不超过 `1`。
- 每次 `get_subagent_result(wait=true)` 前，父 Agent 已完成所有不冲突的本地工作。

最终交付前：

1. 所有已启动代理进入完成、失败或取消终态，不会继续写入。
2. 所有结果均已读取，并明确采用、驳回或转为剩余风险。
3. 失败、超时、未归属或缺失结果不默认为成功。
4. 基于集成后的真实工作区完成最终验证和副作用检查。

能力边界：节点间远程通信不属于本扩展范围；领域技能决定具体审查内容；项目规则决定业务测试和发布门禁。本技能不扩大用户授权，也不自动提交、push、部署或执行其他外部写入。
